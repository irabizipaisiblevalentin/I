# I Toolchain Guide

The I 1.0.0 toolchain is Python-based and installs as a single package (`i-program`). It
provides three layers: the **compiler**, the **virtual machine**, and the **package
manager**. This guide covers the compiler and runtime; see the
[isoko Package Manager Guide](isoko-package-manager.md) for project tooling.

## The Compiler CLI (`i`)

The `i` command compiles `.i` source files to bytecode.

```bash
i --version                      # I Programming Language Compiler v1.0.0
i --help                         # usage and flags
```

| Flag | Meaning |
| --- | --- |
| `-r`, `--run` | compile **and** run the program |
| `-d`, `--disassemble` | print the generated bytecode |
| `-o, --output FILE` | write the compiled bytecode to `FILE` (pickle format) |
| `-v, --verbose` | verbose output |
| `--version` | print the compiler version |

The same CLI is available as a Python module:

```bash
python -m compiler.compiler hello.i -r
```

### Workflow

```bash
# Compile only (no output file)
i hello.i

# Compile and run
i hello.i -r

# Compile, save bytecode, and inspect it
i hello.i -o hello.bc
i hello.i -d
```

### Exit codes and errors

`i` exits with status `0` on success and `1` on any failure. Errors are printed to
standard error in one of these forms:

```
Parse errors:
PARS001 at 1:10 - Unexpected token '"text"', expected 'module path'
  Kinyarwanda: Ikimenyetso '"text"' ntikemewe, byitezwe 'module path'
```

```
Semantic errors:
[ERROR] SEM200_UNDEFINED_VARIABLE file.i:5:24: Undefined variable 'x'
```

```
Runtime Error: Division by zero
```

See the [Error Reference](error-reference.md) for the full code tables.

## The Virtual Machine

Compiled bytecode runs on a stack-based virtual machine. The compiler embeds the
runtime, so `i file.i -r` compiles and executes in one step.

The machine supports:

- global and local (slot-based) variables
- function calls with stack frames
- arithmetic, comparison, bitwise, and unary operations
- conditional and loop jumps
- a garbage-collected heap for lists and strings
- built-in functions (`andika`, `soma`, `ubwoko`, casts)

## Bytecode

Bytecode is a list of instructions from `compiler.codegen.bytecode.OpCode`. Disassemble
a program to inspect it:

```bash
i loops.i -d
```

Example output (trimmed):

```
0000  LOAD_CONST 0
0002  STORE_LOCAL 0
...
```

Bytecode files (`-o`) are Python pickles of the `Chunk` structure and are intended for
tooling and the VM library, not as a portable interchange format yet.

## Embedding the Compiler and VM

Host Python code can drive the whole pipeline:

```python
import stdlib.compiler as c
import stdlib.vm as vm

source = 'andika "Muraho"'
chunk = c.compile_source(source)
vm.run_bytecode(chunk)
```

- `stdlib.compiler.compile_source(source)` → compiled `Chunk`
- `stdlib.compiler.disassemble(chunk)` → disassembly string
- `stdlib.vm.run_source(source)`, `stdlib.vm.run_bytecode(chunk)`, `stdlib.vm.create_vm()`

## Package Manager (`isoko`)

Project scaffolding, builds, tests, and publishing are handled by `isoko`:

```bash
python -m isoko.cli new app
python -m isoko.cli run app
python -m isoko.cli test
```

See [isoko Package Manager Guide](isoko-package-manager.md).

## Editor and Framework Packages

Additional toolchain packages ship in the distribution:

- `istudio` — editor engine primitives (debugger, editor configuration, project
  templates, collaboration)
- `uam` — build configuration and platform manifests
- `ufa` — source-to-source utility package (bootstrap support)
- `urubuga`, `ibiro`, `mobile`, `ububiko`, `ubwenge`, `imikino`, `sisitemu`,
  `igicu` — framework foundation packages

These are developer-facing libraries; the language-facing framework integrations are
tracked in the roadmap.

## Environment and Python

- The toolchain runs on **Python 3.10+** (tested on 3.14).
- `python -m compiler.compiler` may emit a cosmetic
  `RuntimeWarning: 'compiler.compiler' found in sys.modules`; use the `i` entry point
  to avoid it.
- On Windows, make sure the terminal is UTF-8 (`chcp 65001`) for correct output of
  Kinyarwanda text.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| `i` not found | reinstall (`python -m pip install -e .`) or call `python -m compiler.compiler` |
| `ModuleNotFoundError: stdlib` | run from the repository root or reinstall the wheel so `stdlib` is on the path |
| program hangs in `wihuse` | see Known Limitations in the [Language Guide](language-guide.md) — avoid `gukoma` in `wihuse` loops |
| `Build started...` noise | use `--quiet` on `isoko` subcommands |
